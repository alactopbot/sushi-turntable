# 寿司转盘 · MVP

儿童益智小游戏：点选一格寿司，再点相邻格交换；同款连续三个或更多就消掉。在 20 步内收集 300 分。Vite + TypeScript + 原生 Canvas 2D，纯静态，无后端、账号或外部字体/图片请求。

公开游玩地址：**https://alactopbot.github.io/sushi-turntable/**

## 本地运行

Node.js 20.19+（推荐 22），npm：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。手机与电脑在同一局域网时，可打开电脑的局域网 IP 与端口（默认 5173）。输入完全使用 Pointer Events，不依赖键盘。点选高亮后，点击非相邻格会改选；点击同一格取消选择。动画期间不接受新的操作。

```sh
npm test          # 规则与边界条件
npm run build    # TypeScript 检查 + 静态打包
npm run preview  # 预览 dist，默认端口 4173
```

## 冻结规则

- 一关：12 槽；`salmon / tuna / cucumber / egg / shrimp / roe` 六种寿司；20 步；目标 300 分。参数在 `src/game.ts`。
- 唯一消法：相邻交换后，同款连续 ≥3 的完整段消除。首尾相邻，连续段也跨首尾；多段在同一轮动画中一起消除。
- 每次合法交换扣 1 步，包括零消除和相同寿司互换。无消除不回退交换。点击选中、改选均不扣步。
- 环向填补：顶部为 0 号，顺时针依次到 11 号；固定顶部补入口。消除后，保留寿司按原顺序，由顺时针侧沿圆环向空位滑入（索引递减），新寿司从顶部跨过 12→11 的接缝进入。没有网格下落。实现与动画使用同一组 `from/to` 轨迹。
- 填补后仍有三连，自动继续消除，直到稳定；连锁不扣额外步数，不增加特殊块。
- 单段 3/4/5 连为 30/50/80 分，超过 5 格每格 +15。一次交换的第 n 轮消除统一乘 `min(2, 1 + 0.2 × (n − 1))`；同时消除的多段使用同一轮倍率，再累加。
- 当步连锁结束后判断结算：分数 ≥300 胜利（包括最后一步），否则步数为 0 失败。两种结算均可直接「再来一盘」，不刷新页面。
- 开局无现成三连，并保证至少有一手相邻交换可消。随机生成有次数上限及可玩保底，避免死开局。局中不自动洗牌，也不增加第二套规则。

没有点击即消、拖选消除、道具或其他消除方式。六种寿司均直接用 Canvas 绘制，有不同色彩与形状/纹理；命中半径为可视槽位半径的 114%。支持高像素密度屏幕与系统减少动画设置。MVP 无音效。

## 验收复现

自动浏览器验收（首次需安装 Chromium）：

```sh
npx playwright install chromium
npm run test:e2e
```

浏览器测试通过真实指针点击操作；手机项目使用触屏事件。测试使用固定随机种子，并且只读取开发环境的状态快照，不修改盘面、分数或步数。生产构建不暴露快照接口。

| 条目          | 自动验证 / 复现方法                                                                     |
| ------------- | --------------------------------------------------------------------------------------- |
| S1            | 桌面 Chromium 与手机尺寸/触控模拟打开页面，检查页面异常和横向溢出；真实手机仍需人工打开 |
| S2            | 浏览器测试选择可消交换完成胜局；另开一盘先消除一次，再反复做安全零消除交换直到失败      |
| S3–S4         | 两种结算后点击「再来一盘」，检查 20 步、0 分及同一 document 标记                        |
| S5            | 手机项目全局只用触屏完成游戏；实际手指舒适度需真机试玩                                  |
| R1–R2         | 规则测试与浏览器测试检查单击不消除、非相邻只改选；含 11↔0 首尾相邻边界                 |
| R3            | 规则测试构造普通与跨首尾三连，核对填补盘面和每个寿司的圆环移动轨迹                      |

| R6–R7         | 检查六种 ID、12 槽、20 步、目标 300 与 HUD                                              |

## 静态托管

`npm run build` 产物为 `dist/`。`base: './'` 支持站点根目录及 GitHub Pages 仓库子路径，不需要服务端路由重写。

- **Cloudflare Pages**：连接仓库，生产分支 `main`，构建命令 `npm run build`，输出目录 `dist`，Node.js 22。
- **GitHub Pages（生产）**：Settings → Pages 的 Source 设为 **GitHub Actions**。`.github/workflows/build.yml` 对 `main` push 和 PR 执行 `npm ci` → `npm test` → `npm run build`；仅 `main` 在构建成功后通过 `actions/upload-pages-artifact` 上传 `dist/`，再由 `actions/deploy-pages` 部署到上述公开地址。也支持在 Actions 中选择 main 手动运行；PR 只构建，不部署。
- [构建与部署记录](https://github.com/alactopbot/sushi-turntable/actions/workflows/build.yml)：查看 `build`、`deploy` 两个 job 与 `github-pages` 环境链接。浏览器验收单独运行，不增加最小构建 CI 的浏览器安装负担。

回滚：在 Actions → Build 中打开上一条成功部署的运行，选择 **Re-run all jobs**，重新构建并部署该运行原来的 commit（需 GitHub 仍允许重跑）；或对引入问题的提交执行 `git revert <commit>` 并 push 到 `main`，自动触发部署。回滚后确认 `deploy` 成功并刷新公开页面；重跑旧运行不会改变 main，后续 main push 会再次发布 main 的版本。

使用 GitHub Pages 默认免费子域，不设置自定义域名，不更改 DNS。

## 文件

- `src/game.ts`：纯规则、计分、开局与环向填补。
- `src/main.ts`：Canvas 图形、圆环动画、指针输入、HUD 与结算。
- `src/style.css` / `index.html`：移动端布局与页面说明。
- `tests/rules.test.ts` / `tests/browser.spec.ts`：核心规则与完整流程验收。

规则依据任务提供的 `SCOPE-FREEZE.md`、`design/one-pager.md`、`design/acceptance.md`、`playbooks/tech-stack.md`、`PRODUCT.md`，以冻结的一页纸玩法为准。仓库与 `dun` 无代码耦合。
