# 转转寿司 · 流水线 v2.1

从流水线点到盘子里，连成三个就消掉。盘子不能换顺序哦。

Vite + TypeScript + Canvas 2D，手机竖屏可玩，纯静态，无后端或外部图片请求。点弯道流水线上任意可见寿司，追加到盘尾（右侧）。达到目标分过关；盘满且没有可消段则失败。未取的寿司在终点回收，等待不会失败。

## 运行

Node.js 20.19+，npm：

```sh
npm ci
npm run dev
npm test
npm run build
npm run preview
```

## 冻结规则与数据

权威副本：[范围冻结](SCOPE-FREEZE.md)、[一页纸 v2.1](design/one-pager.md)、[验收](design/acceptance.md)、[文案](design/copy.md)。仓内副本与 studio 冻结文件一致。

- 盘内不可重排，满盘不能取餐。每次入盘立即结算连续同款 ≥3 的完整段，多段同帧清除，保留项按原顺序拼接，再判定消除直到稳定。
- 单段分为 `60 × (长度 − 2)`：3=60、4=120、5=180、6=240。第 n 轮消除各段乘 n，不封顶；同轮多段共享倍率。
- 结算完成后优先判断累计分 ≥ 目标分胜利，否则盘满且无可消段失败。成功可进入下一关，第五关后可从第一关重玩；失败可重试，局中可重开本关，均无需刷新。
- 寿司循环供应本关前 N 种；出餐受间隔、线上数量和出口空间限制。移动速度与路径坐标是表现参数。五关路径逐渐增长，第三关起出现回折弯道。

| 关 | 盘格 | 种类 | 目标分 | 线上上限 | 出餐间隔 |
|---|---|---|---|---|---|
| 1 | 8 | 3 | 180 | 4 | 1.2 秒 |
| 2 | 7 | 4 | 300 | 5 | 1.1 秒 |
| 3 | 6 | 4 | 420 | 5 | 1.0 秒 |
| 4 | 6 | 5 | 540 | 6 | 0.9 秒 |
| 5 | 5 | 5 | 660 | 6 | 0.8 秒 |

**冻结规则的可达性边界**：空盘开始、每次只入尾一枚且立即结算三连时，稳定盘面每段至多两枚；新匹配只能在盘尾形成三连，清除后也没有右侧残留可拼接。因此正常游玩只能触发三消，四消及拼接连锁无法自然产生。引擎完整支持长段与多轮拼接，规则测试通过构造盘面验证；未添加延迟结算或重排来改变冻结玩法。这也意味着验收 R3/R4 的四消、连锁实机飘分部分尚不能通过正常游玩复现。

## 验证

```sh
npx playwright install chromium
npm run test:e2e
```

- `npm test` 覆盖精确五关表、任意位置取餐、尾部追加、容量限制、最后一格消除、同时多段消除、三轮拼接连锁、3/4/5/6+ 分档和段序倍率、胜负优先级、终局锁定、出餐间隔/上限/回收。
- 浏览器测试使用真实鼠标或触屏事件完成五关胜利、返回第一关、满盘失败及不刷新重试；验证中段取餐、盘内点击不重排、空转回收、文案、页面异常及横向溢出。使用模拟时钟加快等待，只读取开发环境快照，不修改游戏状态；生产构建不暴露快照。
- 截图输出 `test-results/`，不入仓。手机测试是 Chromium 触屏模拟；真实设备触控舒适度及儿童试玩仍需人工验收。消除淡出与飘分可见，减少动画偏好会缩短结算动画。

## 文件与发布

- `src/game.ts`：取餐、消除、计分、胜负和流水线推进。
- `src/levels.json`：五关数据；`src/path.ts`：弯道路径。
- `src/main.ts`：Canvas 绘制、取餐输入、消除动画、HUD 和重试/下一关。
- `tests/rules.test.ts`、`tests/browser.spec.ts`：规则与完整操作流程。

`npm run build` 输出 `dist/`；相对资源路径支持 GitHub Pages 仓库子路径。现有 `.github/workflows/build.yml` 在 main push 后测试、构建并部署至免费站点： https://alactopbot.github.io/sushi-turntable/ 。无自定义域名/DNS 变更，与 dun 无耦合。

回滚可 revert 对应提交后 push main，让现有工作流重新发布。
